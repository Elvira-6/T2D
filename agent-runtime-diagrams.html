1状态机图 · AgentStage 阶段转移

8 个阶段由「决策策略 decideNextAction」驱动转移，每个箭头上的标签是触发转移的动作。

stateDiagram-v2 [*] --> IDLE : 初始化 IDLE --> PLANNING : PLAN PLANNING --> GENERATING : GENERATE GENERATING --> VALIDATING : VALIDATE VALIDATING --> REPAIRING : REPAIR
(errors > 0) REPAIRING --> VALIDATING : VALIDATE
(errors 清空) VALIDATING --> COMPLETED : DONE IDLE --> FAILED : FAIL（步数耗尽） PLANNING --> FAILED : FAIL GENERATING --> FAILED : FAIL VALIDATING --> FAILED : FAIL REPAIRING --> FAILED : FAIL WAITING_HUMAN : 预留阶段（人工介入，Phase 0 未接入） COMPLETED --> [*] FAILED --> [*]
两个终态：COMPLETED（正常交付）与 FAILED（步数耗尽）。 自愈回路：VALIDATING ⇄ REPAIRING，校验发现 errors 就回退修复，修完重新校验。 WAITING_HUMAN 在类型里已定义，但当前决策策略从未跳到它——留给后续人工确认场景。

怎么读：最上面的 UI 调用 index.ts，入口把 runAgent 暴露出去。 中间的 runtime 是中枢，它按循环顺序做三件事——① 决策（问 policy 下一步干啥）、 ② 执行（按动作查 tools 注册表）、③ 记录（用 state/events 追加事件）。 而 policy / tools / state+events 三块都只依赖最底层的 types.ts——这就是「契约是地基」： Phase 1~4 接入真实 LLM 时，只需替换 tools 这一块，其余层不动。
